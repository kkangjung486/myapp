# KCFM 기업 현금흐름 진단 (MVP)

매출 5억~100억 원 규모 중소기업의 **3개년 재무제표 PDF**를 올리면
**"현금이 어디에 묶였고, 영업에서 현금이 만들어지고 있는지"**를 신뢰할 수 있는 숫자로 보여주는 컨설팅 도구입니다.

- 회계 프로그램이 아닙니다. 컨설턴트가 고객사의 현금흐름 구조·운전자본 문제를 빠르게 파악하기 위한 도구입니다.
- 모든 지표는 **PDF에서 읽은 숫자**를 **정해진 계산식**으로 계산합니다. AI가 숫자를 추측하지 않습니다.
- 숫자를 읽지 못하거나 애매하면 임의로 채우지 않고 **"확인 필요"**로 표시합니다.

---

## 1. 설치 (처음 한 번만)

1. **Python 설치** — <https://www.python.org/downloads/> 에서 Python 3.10 이상을 내려받아 설치합니다.
   Windows는 설치 첫 화면에서 **"Add python.exe to PATH"** 에 반드시 체크하세요.
2. 이 폴더(`kcfm_cashflow`)를 PC의 원하는 위치에 복사합니다.

> 개발자용: `pip install -r requirements.txt`

## 2. 실행

- **Windows**: `실행하기_Windows.bat` 파일을 더블클릭
- **Mac**: `실행하기_Mac.command` 파일을 더블클릭 (처음에 보안 경고가 뜨면 우클릭 → 열기)

처음 실행할 때는 필요한 프로그램을 자동으로 설치하느라 몇 분 걸립니다.
잠시 후 웹브라우저에 앱이 열립니다(주소: `http://localhost:8501`). 열리지 않으면 이 주소를 직접 입력하세요.
종료하려면 검은 실행 창을 닫으면 됩니다.

> 명령어로 실행: `streamlit run app.py`
>
> 모든 처리는 **내 PC 안에서만** 이루어지며 재무제표가 외부로 전송되지 않습니다.

## 3. 사용 순서

### ① PDF 업로드
1. **업종**을 선택합니다 (제조업 / 도소매업 / 건설업 / 서비스업 / 기타).
2. 최근 3개년 재무제표 PDF를 올립니다. 예: `2023년 재무제표.pdf`, `2024년 재무제표.pdf`, `2025년 재무제표.pdf`
   - 한 PDF에 3개년이 모두 들어 있어도 됩니다.
   - 각 PDF의 **전기 열**도 읽습니다. 그래서 2023년 PDF의 2022년 숫자로 첫 해의 평균잔액·증감까지 계산합니다.
3. **[PDF 읽기]** 를 누릅니다. 처음이라면 **[샘플 데이터로 체험하기]** 로 가상 제조업체 예시를 먼저 보세요.

### ② 데이터 확인 ("재무제표 추출 결과 확인") — 가장 중요
분석 전에 반드시 이 화면에서 숫자를 확인합니다.

1. **파일별 인식 정보**: 단위(원/천원/백만원)와 연도가 원본 PDF와 맞는지 봅니다.
   틀렸다면 표에서 고치고 **[단위·연도 수정 반영]** 을 누릅니다.
2. **연도별 표**: 연도 탭마다 아래 항목이 나옵니다.

   | 재무제표 | 원본 계정명 | 원문 숫자 | 단위 | 추출금액(원) | **확인금액(원) ✎** | **표준 계정 ✎** | **분석 포함 ✎** | 상태 | 메모 |
   |---|---|---|---|---|---|---|---|---|---|

   - 잘못 읽힌 숫자는 **확인금액(원)** 에서 고칩니다. 원본 추출금액은 따로 보관됩니다.
   - **상태가 "확인 필요"** 인 계정(선급금·선수금·미지급비용 등)은 **메모의 제안을 참고해 표준 계정을 선택**합니다.
   - 빠진 계정은 표 아래 **+** 로 행을 추가해 직접 입력할 수 있습니다(스캔 PDF 등).
3. **숫자 검증** 결과(자산=부채+자본, 손익 합계 등)를 확인합니다.
4. **[분석 시작 ▶]** 을 누릅니다.

### ③ 분석 결과
| 탭 | 내용 |
|---|---|
| 핵심 요약 | 영업활동현금흐름, 영업운전자본, DSO·DIO·DPO·CCC, 현재 현금, 총차입금 + 3개년 그래프 |
| 돈이 어디에 묶였나 | "우리 회사의 돈은 어디에 묶여 있을까요?" — 매출채권·재고·매입채무·유형자산·차입금 변화와 설명 문장 |
| 영업활동현금흐름 | 공시값과 추정값 비교, 추정 계산 내역 |
| 운전자본 | 순운전자본(NWC)과 영업운전자본(OWC) 구분, 증감 해석 |
| 현금전환주기(CCC) | 계산 내역, 평균잔액/기말잔액 사용 여부, DPO 분모 기준 |
| 진단 신호 | 관찰 · 주의 · 집중점검 단계의 위험 신호 |
| 검증·계산근거 | 검증 결과, 표준화 재무데이터, 계산식 |

### ④ 결과 다운로드
결과 화면 상단의 **[분석 결과 Excel 다운로드]** 를 누릅니다.
시트: 기업 기본정보 / 3개년 추출 재무제표(원본값·수정값 구분) / 표준화 재무데이터 / 현금흐름 분석 / 운전자본 분석 / CCC 분석 / 진단 결과 / 검증 결과 / 계산식

## 4. 계산식

| 지표 | 계산식 |
|---|---|
| 공시 영업활동현금흐름 | 현금흐름표의 "영업활동으로 인한 현금흐름" (있으면 우선 사용) |
| 추정 영업활동현금흐름 | 당기순이익 + 감가상각비 + 무형자산상각비 + 퇴직급여충당부채(순액) 증가 − 매출채권 증가 − 계약자산 증가 − 재고 증가 − 기타영업유동자산 증가 + 매입채무 증가 + 계약부채 증가 + 기타영업유동부채 증가 |
| 영업현금흐름률 | 영업활동현금흐름 ÷ 매출액 × 100 |
| 현금이익전환율 | 영업활동현금흐름 ÷ 당기순이익 (순이익 0 이하이면 해석 불가) |
| 순운전자본 NWC | 유동자산 − 유동부채 |
| 영업운전자본 OWC | 매출채권 + 계약자산 + 재고자산 + 선택된 기타영업유동자산 − 매입채무 − 계약부채 − 선택된 기타영업유동부채 |
| DSO | 평균 매출채권 ÷ 매출액 × 365 |
| DIO | 평균 재고자산 ÷ 매출원가 × 365 |
| DPO | 평균 매입채무 ÷ 연간 매입액 × 365 (매입액 = 당기상품매입액 + 당기원재료매입액. 없으면 매출원가 대용 + 표시) |
| CCC | DSO + DIO − DPO |
| 평균잔액 | (전기말 + 당기말) ÷ 2. 전기말 자료가 없으면 기말잔액 사용 + 표시 |
| 총차입금 | 단기차입금 + 유동성장기부채 + 장기차입금 + 사채 (리스부채 제외) |

## 5. 폴더 구조

```
kcfm_cashflow/
├── app.py                    # 앱 시작점 (화면 흐름)
├── config/                   # ★ 설정 (비개발자도 수정 가능)
│   ├── accounts.py           #   표준 계정 목록, 차입금·운전자본 구성
│   ├── mapping_rules.py      #   계정명 → 표준계정 매핑 규칙
│   ├── industry_rules.py     #   업종별 진단 포인트 (기준치는 추후 추가)
│   └── diagnostic_settings.py#   진단 신호 임계값
├── pdf_parser/               # PDF → 숫자 (텍스트 레이어 우선, 스캔본만 OCR)
├── account_mapper/           # 계정 표준화 (차감계정·소계·부호 처리)
├── data_pipeline/            # 추출표 생성, 연도별 자료 선택, 수정 반영, 표준화 집계
├── financial_calculations/   # 재무계산 (PDF와 완전히 분리 — 단위 테스트 대상)
├── diagnostic_rules/         # 자동 진단 규칙
├── export/                   # Excel 다운로드
├── ui/                       # 화면 구성
├── sample_data/              # 가상 제조업체 원천데이터 + 샘플 PDF 생성기
└── tests/                    # 단위·통합 테스트
```

## 6. 테스트 실행 (개발자용)

```bash
python -m pytest            # 전체 테스트
python -m sample_data.generate_sample_pdfs   # 샘플 PDF 다시 만들기
```

## 7. OCR (선택)
스캔 PDF는 텍스트가 없어 자동으로 읽을 수 없습니다. OCR을 쓰려면
[Tesseract](https://github.com/UB-Mannheim/tesseract/wiki)를 **한국어(kor) 언어팩과 함께** 설치하고
`pip install pytesseract pillow` 를 실행하세요. OCR로 읽은 숫자는 모두 "확인 필요"로 표시됩니다.
OCR이 없어도 검증 화면에서 숫자를 직접 입력해 분석할 수 있습니다.
